Struts 1.1 EOL since 2013 with known RCE. Spring 4.3 EOL 2020. Java 8. No security patches available for core framework vulnerabilities.

Operational Fragility

98 point-to-point connections, zero circuit breakers. Central app has 27+ downstream calls — a single failure cascades silently across the platform.

Talent & Cost Pressure

Shrinking pool of EJB/Struts/WebLogic developers. Acute key-person risk. Expensive onboarding. Proprietary app server licensing growing with no exit path.

Risk of Inaction

2–3 year horizon: rising incident frequency, GDPR fines exposure, key-person loss threatening operations, and inability to deliver new capabilities at business pace.

These aren't hypothetical risks — they're live findings backed by code evidence. The first three are existential risks. The last three are strategic blockers. The cost of not acting is higher than the cost of acting.

Modernization Roadmap

Phased strangler-fig approach — the existing platform keeps running throughout

Roadmap

6-Phase Modernization Roadmap

0
Foundation
Kubernetes cluster, CI/CD pipelines, OAuth 2.0, OpenAPI registry. No user-facing changes.
Gate: Infrastructure operational, CI/CD running
1
Front-end & BFF
React/Vue SPA for first app. BFF layer connecting to existing services. Pilot users validate.
Gate: Pilot stable, BFF handling production data
2
Service Migration
Services migrated to Spring Boot / containers. SOAP converted to REST. Tests generated.
Gate: Migrated services stable, automated tests established
3
API Gateway & Integration
Unified API Gateway with rate limiting, routing, OAuth 2.0. Fragmented auth retired.
Gate: All traffic through gateway, auth consolidated
4
Consolidation
Overlapping services merged. Business logic consolidated. Legacy app server decommissioned.
Gate: Business logic consolidated, legacy server retired
5
Data Independence
Shared database split: each service owns its data store. Event-based synchronization.
Strangler Fig: Platform stays live throughout. Legacy components retire only after production proof.
The strangler fig pattern is key. The existing system never goes down — new capabilities wrap it and traffic shifts gradually. Every phase has a gate, so we manage risk at every step. Phases 0–2 can often be done in parallel.
